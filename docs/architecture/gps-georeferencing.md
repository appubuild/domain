# Phase 6 — GPS and georeferencing (partial)

## Device location

On supported secure browser contexts, the user can request a **single** Geolocation API fix. No permission request occurs on page load. The UI presents latitude/longitude in WGS84, the device-reported accuracy radius in metres and timestamp. A separate action centers the map; stale fixes (over 60 seconds) and latitudes outside Web Mercator cannot be used to center. Invalid values, denial, unavailability and timeout are reported without changing the drawing. Cancel invalidates the pending callback but cannot cancel the browser's native permission dialog or hardware request. Clearing or leaving the page removes the displayed fix. This app does not put the fix in projects or send it to its own server; an enabled online basemap can receive tile requests for the area viewed when the map is centered. GPS accuracy is device-reported, variable and not proof of cadastral accuracy.

## Temporary reference image

A user selects a local PNG/JPEG, then supplies the image's already-known **north-up WGS84 rectangular bounds** in decimal degrees. The application places the image between the basemap and drawing layers, at fixed 65% opacity. This is rectangular visual placement, not control-point estimation or a reprojection; it does not correct rotation, skew, terrain or image distortion. It refuses inverted, out-of-projection and antimeridian-spanning bounds. Files must be at most 8 MiB, no more than 8192 pixels on either axis and no more than 16 million pixels. PNG/JPEG signatures and declared dimensions are checked before the browser decodes, and the decoded dimensions are checked again. These checks do not guarantee that all malformed images or device memory constraints are handled safely. Failed replacement attempts preserve the previous overlay where possible. An image being loaded is not applied if a drawing starts in the meantime.

The image remains local to the current browser page and can be removed. **It and the entered alignment are not saved, exported, included in backup or reports, or restored after reload.** Users must retain their original file and bounds independently. It is not an official map or legal boundary, and the accuracy depends entirely on the entered bounds and source material. Location and image data are not encrypted by the browser or the app against a person with access to the device. No server upload, tracking or location history is implemented.

## Evidence and limitations

Headless Chromium tests use browser-simulated coordinates and permission grant/denial, invalid/stale and cancelled callbacks, and synthetic PNG/JPEG images. Tests inspect rendered raster pixels, layer ordering after basemap switching, invalid replacement, removal and preservation of drawing. English/Bengali layouts were tested at 320, 375, 430, 768, 1024, 1366 and 1920 px, plus 667×375 and 932×430 landscape. Axe scans covered the GPS/reference controls in both languages at 320 and 1366 px, without establishing complete accessibility conformance. Actual GPS hardware, real permission UI, physical mobile performance, other browsers, independent georeferencing accuracy, advanced control points and persistent image storage remain unverified or unimplemented. Phase 6 is not production-ready.
