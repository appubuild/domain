# Deployment

DomainFits is a **static export**. `npm run build` writes a self-contained `out/` directory;
whatever host you use must be able to serve HTML files and, ideally, rewrite rules.

```
out/
├── index.html                     # /
├── generator/index.html           # /generator/
├── industries/…                   # directory pages (17 industries)
├── blog/…                         # index + articles
├── about/ contact/ faq/ …         # CMS pages
├── admin/…                        # admin SPA routes (auth-gated, noindex)
├── 404.html
├── _next/                         # hashed CSS/JS chunks
├── robots.txt
├── sitemap.xml
├── .htaccess                      # Apache rules (generated)
├── _redirects                     # Netlify / Cloudflare Pages (generated)
└── redirects.json                 # audit copy of the compiled rules
```

---

## 1. Environment

Copy `.env.example` to `.env.local` (or export the variables in CI) **before** building. All
values are public and inlined at build time.

| Variable | Required | Effect when missing |
| --- | --- | --- |
| `NEXT_PUBLIC_APP_URL` | For SEO | Canonicals, Open Graph URLs and sitemap entries are omitted; the build logs a warning |
| `NEXT_PUBLIC_SITE_NAME` | No | Falls back to `DomainFits` |
| `NEXT_PUBLIC_SUPABASE_URL` | For CMS/admin | Site builds from the offline content pack; admin shows "not configured" |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | For CMS/admin | Same as above |
| `NEXT_PUBLIC_DATA_BACKEND` | No | `local` when Supabase is absent |
| `NEXT_PUBLIC_AVAILABILITY_FN_URL` | No | Availability runs directly against RDAP from the browser |
| `NEXT_PUBLIC_ALLOW_LOCAL_STORE` | No | `false`; never enable in production |

Secrets — service-role keys, registrar keys, AI provider keys — must never appear here. They
belong in Supabase Edge Function secrets. See [`security.md`](security.md).

The canonical origin must match exactly where the site is served, including `https://` and
excluding a trailing slash. A mismatch splits canonical signals, so rebuild after any host change.

## 2. Shared hosting (Apache + PHP, no Node)

1. `npm ci && npm run build`
2. Upload the **contents** of `out/` to `public_html/` (or a subdirectory).
3. Confirm hidden files were transferred — `.htaccess` is easy to miss and without it you lose
   redirects, the 404 handler and directory-index hardening.
4. Set the document root to the uploaded folder. Do not upload `src/`, `node_modules/` or `supabase/`.

`out/.htaccess` is generated by `scripts/emit-hosting-config.ts` after `next build`. It holds
three things that a static export cannot express in code:

```apache
<IfModule mod_rewrite.c>
  RewriteEngine On
  # canonical host + protocol (only when NEXT_PUBLIC_APP_URL is https)
  RewriteCond %{HTTPS} off [OR]
  RewriteCond %{HTTP_HOST} !^example\.com$ [NC]
  RewriteRule ^ https://example.com%{REQUEST_URI} [R=301,L]
  # database redirects, e.g.
  RewriteRule ^old-page/?$ /new-page/ [R=301,L]
</IfModule>

# security headers — see docs/security.md §9
<IfModule mod_headers.c>
  Header always set Content-Security-Policy "default-src 'self'; …"
  Header always set X-Content-Type-Options "nosniff"
  Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
  # content-hashed assets never change; HTML always revalidates
  <FilesMatch "-[0-9a-f]{16}\.(js|css)$">
    Header set Cache-Control "public, max-age=31536000, immutable"
  </FilesMatch>
</IfModule>

# compression
<IfModule mod_deflate.c>
  AddOutputFilterByType DEFLATE text/html text/css application/javascript …
</IfModule>

ErrorDocument 404 /404.html
DirectoryIndex index.html
Options -Indexes
```

Two behaviours worth knowing:

- **Caching is the difference between a fast and a slow deployment.** Next names every asset
  with a content hash, so `_next/static` files are safe to cache for a year. Without that header
  each navigation revalidates megabytes. HTML is deliberately *not* cached: a rebuild must be
  visible immediately.
- **Every section is wrapped in `<IfModule>`.** On a plan without `mod_headers` or `mod_deflate`
  the site still serves; you lose the headers, not the pages.

Verify after upload:

```bash
curl -sI https://example.com/ | grep -Ei 'content-security-policy|x-content-type|cache-control'
curl -sI https://example.com/_next/static/chunks/$(ls out/_next/static/chunks | head -1)
```

Trailing slashes are part of the URL contract (`trailingSlash: true`). `/about` is served from
`about/index.html`; Apache's `mod_dir` issues the `/about` → `/about/` redirect automatically.
If `mod_rewrite` is unavailable on your plan, the site still serves correctly but the redirects
and canonical-host consolidation do nothing — check with your host.

### Deploying into a subdirectory

Set `NEXT_PUBLIC_APP_URL=https://example.com/domainfits` **and** add `basePath: "/domainfits"`
to `next.config.ts` before building. Without the base path the asset URLs will 404.

## 3. Netlify / Cloudflare Pages

- Build command: `npm run build`
- Publish directory: `out`
- Use `out/_redirects` (already generated) instead of `.htaccess`.
- Use `out/_headers` (already generated) for the security and caching headers. It carries the
  same policy as the Apache file, including the immutable cache for `_next/static`.

Both hosts apply `_redirects` and `_headers` before serving files, so database redirects and the
header set work without Apache.

### What a push actually does

Observed behaviour on this project (verified, not assumed):

| Push | Result |
| --- | --- |
| to `arena/b181432b-domain` (any non-production branch) | a **preview** deployment is created automatically and aliased to `domainfits-git-arena-…vercel.app`; `domainfits.vercel.app` does **not** change |
| to `main` (the project's production branch) | a **production** deployment, which takes the `domainfits.vercel.app` alias |

The project object still reports `gitProviderOptions.createDeployments = "disabled"`, which
contradicts the two preview builds created from pushes (`dpl_7H4j34NR…`, `dpl_6JATaYT4…`).
Trust the deployments list over that flag. If a future push does *not* produce a build, enable
Project → Settings → Git → *Deploy on push*, or create one explicitly:

```
POST /v13/deployments
{"name":"domainfits","project":"prj_hU5cKmOSxtqOUAnQve0MAWPiIEU7","target":"production",
 "gitSource":{"type":"github","ref":"<branch>","repoId":1382063430}}
```

Because the output is static, **a content edit is not live until a deployment finishes.** Plan
edits around deploys rather than expecting them to appear immediately.

### Verifying a deployment

```bash
curl -s https://<deployment-url>/redirects.json   # source: "supabase" proves the DB read worked
curl -s https://<deployment-url>/sitemap.xml | head -c 200   # absolute URLs prove APP_URL was set
```

`redirects.json` is the honest signal: `scripts/emit-redirects.ts` prints a warning and reports
the same information in the build log when the Supabase read fails, and writes `"source":
"supabase"` only after a 2xx response. An empty `redirects` array with `"source": "supabase"`
means "the table is empty", not "the read failed".

## 5. Supabase

```bash
supabase login
supabase link --project-ref <ref>
supabase db push --include-seed     # migrations 0001–0008 + seed data
```

Then:

1. Authentication → create your admin user; disable public sign-ups unless needed.
2. SQL editor: `insert into public.user_roles (user_id, role_id) values ('<uuid>', 'admin');`
3. Copy the project URL and **anon** key into `.env.local`, rebuild.
4. Storage: migration `0007_media_storage.sql` creates the public `media` bucket and its
   administrator-only write policies. Confirm it in Storage → Buckets. If you created a
   bucket by hand earlier, check it is named exactly `media`; the admin library hard-codes
   that name and uploads fail closed otherwise.

   The bucket is public because the exported site is static HTML: a signed URL would expire
   while still cached in the page. Only administrators can write to it, and the four accepted
   formats (JPEG, PNG, WebP, AVIF) are enforced by both the upload screen and a table
   constraint. SVG is refused deliberately — an uploaded SVG is stored XSS on a public origin.

**Current project:** `DomainFits` (`bjbbrgjiyoquacoypsia`) already has migrations `0001`–`0008`
applied and the seed loaded (verified: 44 tables, 0 without RLS, 80 policies, `media` bucket
present). The remaining manual steps are the admin account and `NEXT_PUBLIC_APP_URL` — see
[`phase-9-report.md`](phase-9-report.md) §5.

RLS is enabled on all 44 tables, so the anon key is safe in the browser. Verify with:

```sql
select tablename, rowsecurity from pg_tables
where schemaname = 'public' and rowsecurity = false;   -- must return zero rows
```

### Edge Functions (optional)

- **Availability proxy** — `supabase/functions/availability/index.ts`. Centralises RDAP calls,
  caches answers in Postgres (`availability_cache`, 6 h definitive / 10 min inconclusive) and
  returns the same result shape as the client engine. Deploy with:

  ```bash
  supabase functions deploy availability --no-verify-jwt
  # then set NEXT_PUBLIC_AVAILABILITY_FN_URL=https://<ref>.supabase.co/functions/v1/availability
  ```

  Without it the site still checks names, calling public RDAP endpoints directly from the
  browser; registries that refuse cross-origin requests show up as failed checks, never as
  available.

- **Affiliate click-through** — `supabase/functions/affiliate-click/index.ts`. Re-validates the
  provider, host allowlist and `affiliate_routing` flag server-side, records the click and issues
  the 302. Deploy with `supabase functions deploy affiliate-click --no-verify-jwt`, then set
  `NEXT_PUBLIC_AFFILIATE_FN_URL`. Without it, links are built (and validated) in the browser and
  clicks are recorded best-effort.
- **AI content studio** — drafts only, never auto-publishes. Requires a provider key stored as a
  function secret; the feature stays off until `feature_flags.ai_content_studio = true`.

Deploy with `supabase functions deploy <name> --no-verify-jwt` only where a function is truly
public; anything that writes must verify the caller's JWT and role.

## 6. Going live checklist

- [ ] `NEXT_PUBLIC_APP_URL` set to the final origin, then rebuilt
- [ ] `out/.htaccess` present and `https` + canonical host resolve with one 301 hop
- [ ] `robots.txt` allows crawling and disallows `/admin/`
- [ ] `sitemap.xml` lists absolute URLs (view source — an empty `<urlset>` means the origin is unset)
- [ ] submitted sitemap in Search Console
- [ ] admin sign-in works and a non-admin account is correctly refused
- [ ] redirects from the admin table reach the live site after a rebuild
- [ ] ad slots stay disabled until a publisher ID and consent flow exist
- [ ] previous `out/` kept as the rollback artifact

## 7. Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Asset 404s, unstyled page | Uploaded into a subdirectory without `basePath` | See §2 |
| `/about` 404 | Only `about.html` uploaded, or `DirectoryIndex` overridden | Upload `about/index.html`; check `.htaccess` |
| Redirects do nothing | `mod_rewrite` disabled, or `.htaccess` not uploaded | Ask host; verify with `curl -I` |
| Sitemap empty | `NEXT_PUBLIC_APP_URL` missing at build time | Set it and rebuild |
| Admin shows "not configured" | Supabase env vars absent from the build | Set both vars, rebuild |
| Admin shows "no administrator role" | Signed in without `user_roles` row | Insert the row in SQL, reload |
| Content edits do not appear | Static export serves bytes baked at build time | Rebuild and re-upload (on Vercel: trigger a deployment, §4) |
| A push produced no deployment | Git integration not active for that branch, or the project's `createDeployments` flag blocks it | Enable Project → Settings → Git → *Deploy on push*, or deploy explicitly (§4) |
| Push built a preview but `domainfits.vercel.app` is unchanged | Only the production branch (`main`) moves the production alias | Merge to `main`, or create a deployment with `"target":"production"` (§4) |
| Vercel build used the offline content pack | `NEXT_PUBLIC_SUPABASE_*` missing for that environment, or the REST read failed | Check the build log for the `[redirects] … (source: …)` line; set the vars and redeploy |
| Dev server 500s with `Cannot find module './NNN.js'` or `ENOENT .../app-paths-manifest.json` | `npm run build` ran while `next dev` was live and rewrote `.next`; dev and build share that directory | Stop the dev server, `npm run clean`, then restart. `npm run build` now refuses to run while something listens on port 3000 (override with `DOMAINFITS_ALLOW_BUILD_WITH_DEV=1`) |

## 8. Rollback

The previous `out/` directory is a complete, independent release. Keep the last known-good copy;
restoring it is a file copy, not a migration. Database rollback is a Supabase backup restore —
take one before `db push` and before bulk content changes.
